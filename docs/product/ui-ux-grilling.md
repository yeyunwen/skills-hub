# skills-hub UI/UX 访谈记录

- 状态：Discovery
- 日期：2026-07-23
- 范围：桌面端信息架构、SSH 同构体验、Skill 状态术语、窗口适配、视觉与动效方向

## 已确认诉求

1. SSH 设备应当是一等入口，不应先进入“远程设备”页面，再从设备列表进入管理内容。
2. 进入 SSH 设备后的功能、页面结构和交互，应尽量与本机一致。
3. “已启用 / 待启用 / 待处理”不能准确表达 Skill 是否进入统一管理中心。
4. 冲突应直接命名为“冲突”，不再使用含糊的“待处理”代替。
5. 当前界面不够简洁，视觉层级、操作路径和小屏窗口适配需要整体重做。
6. 在确定参考方向前，不直接猜测最终视觉方案。

## 当前实现观察

- 左侧导航把“本机管理”和“远程设备”作为两种不同功能。
- 远程设备页内部仍有设备列表、Agent 选择、传输和同步等二级操作。
- 本机页提供 Skills、待纳管、目录诊断三个视图，远程页没有同构入口。
- 当前窗口最小尺寸为 `980 × 640`，侧栏固定 `248px`。
- 主界面存在固定四列卡片、`340px + 内容区` 双栏等布局，小窗口下缺少明确的降级策略。
- 当前状态文案同时混用了“是否进入 Hub”“是否分发到 Agent”“是否发生异常”三种含义。

## 三张参考图确认

### 图一：Codex 左侧项目列表

- 本地项目和 SSH 项目出现在同一层级。
- SSH 只是项目所在位置或连接上下文，不是需要先进入的独立功能页。
- 项目可以直接展开其下属任务，不需要先打开“远程设备列表”再选择设备。
- 该图片目前只确认了导航结构参考，尚未确认整个产品都要复制其视觉风格。

### 图二：当前远程设备页

- 需要先进入“远程设备”，再从页面内部选择具体 SSH 设备。
- 远程页使用“本机与远端对比、传输 Skill、同步到远程”的专用工作流。
- 设备选择、Agent 选择和 Skill 操作堆叠在同一页，形成明显的二级入口和较高认知负担。
- “已同步、待同步到远端、仅远端”表达的是跨环境差异，不是当前环境自身的 Skill 管理状态。

### 图三：当前本机管理页

- 已经具备 Skills、待纳管、目录诊断三个主要视图。
- 远程环境若要与本机一致，应优先复用这套页面结构和操作，而不是继续扩展图二的专用页面。
- “已启用、待启用、待处理”仍需要按纳管、同步和冲突重新命名。

## 当前信息架构假设

左侧直接列出可管理环境：

```text
环境
  本机
  hermes              SSH
  office-mac          SSH

安装来源
设置
```

点击任意环境后，主内容复用同一套管理界面：

```text
Skills | 待纳管 | 目录诊断
```

跨环境传输或对比不再作为远程环境的默认首页，而是独立的次级操作。

## 2026-07-23 已确认决策

1. 点击任意环境后直接进入该环境的 Skills 页面，不在侧栏展开二级功能。
2. SSH 环境复用本机环境的页面结构和主要交互。
3. 整体视觉与交互参考 Codex，不只参考左侧导航。
4. Skills 页面保留统计摘要。
5. “与本机对比 / 传输 Skill”是否保留尚未最终确认。

## 2026-07-26 补充确认

1. 本机和每台 SSH 设备都是完全独立、地位平等的环境。
2. 每个环境拥有自己的统一技能库和 Agent 状态，不以本机作为默认主环境。
3. 跨环境对比和传输需要保留，用于多台电脑之间的显式协作。
4. 对比和传输不是 SSH 环境的默认管理模式，也不改变环境彼此独立的原则。
5. 深色模式是正式需求。
6. 命令面板、右键菜单和完整快捷键体系尚未进入确定范围。
7. 动效范围需要拆分为页面转场、连接反馈、列表变化和弹层反馈后再确认。

## 待确认领域模型

### 环境

一个可以独立管理 Skill 的运行环境。

- 本机环境
- SSH 环境

每个环境原则上都拥有相同的功能入口：

- Skills
- 待纳管
- 目录诊断
- 安装来源
- 设置或环境配置

### Skill 生命周期

Skill 状态拆成相互独立的三个维度：

1. 纳管状态：建议使用已纳管 / 待纳管
2. 分发状态：已同步 / 未同步 / 冲突
3. 连接状态：已连接 / 连接中 / 离线 / 连接失败

推荐理由：

- `注册`容易被理解为只写入一条配置记录，但实际操作涉及复制、移动、备份和建立链接。
- `纳管`能表达 Skill 已进入当前环境统一技能库并由 skills-hub 管理。
- 操作使用“纳入技能库”，摘要和筛选使用“已纳管 / 待纳管”，减少企业术语感。

1. 左侧是否采用“环境列表”，本机与每台 SSH 设备都是同一级入口？
2. 点击环境后，主内容是否完全复用同一套页面，只改变数据来源、连接状态和顶部环境标识？
3. “安装来源”是每个环境独立配置，还是只在本机配置后再同步到远程？
4. SSH 环境是否允许直接编辑远端 Hub，还是所有写入都必须以本机 Hub 为真源？
5. “注册”是否专指 Skill 已进入该环境的 Hub（本机可配置，SSH 当前默认为 `~/.agents/skills`）？
6. Agent 目录存在同名真实目录时，是否统一显示“冲突”，并提供“查看差异 / 保留 / 备份并接管”？
7. 最小支持窗口尺寸是多少，是否允许窄窗口自动折叠侧栏和卡片列？
8. 视觉方向更接近 Codex、Linear、Raycast，还是更偏原生 macOS 工具？
