# 当前界面视觉诊断

- 状态：Discovery
- 日期：2026-07-26
- 证据：用户提供的本机管理、远程设备和 Codex 侧栏截图

## “颗粒感”的具体来源

### 表面层级过多

- 页面、顶部分段、统计区、内容卡片、Agent 卡片和状态小卡片层层嵌套。
- 每一小块内容都有边框、圆角或背景，界面被切成大量独立颗粒。
- 信息关系主要依靠盒子表达，而不是间距、对齐和字体层级。

### 状态元素过多

- 绿色按钮、绿色背景、红色背景、灰色背景、圆点、Badge 和图标同时出现。
- Agent 身份、可操作状态和异常状态争夺视觉注意力。
- 主操作和普通状态都使用较强颜色，缺少稳定视觉焦点。

### 字体层级分散

- 页面标题、区块标题、统计数字、Badge、说明和路径同时使用多种字号与字重。
- 中文、英文、品牌名和等宽路径缺少统一基线。
- 小号灰色文字偏多，信息虽然存在，但阅读顺序不明确。

### 密度分布不均

- 上半部分多个区域非常紧密，下半部分却存在大面积空白。
- 卡片内部操作拥挤，但整体页面没有形成连续的列表阅读节奏。
- 固定列数在小窗口下容易挤压，在宽窗口下又留下无意义空白。

### 操作权重不清

- 刷新、删除、批量启用、传输和同步等按钮同时占据显著位置。
- 行级状态与行级操作排列接近，用户需要逐项判断哪些可点击。
- SSH 专用动作打断了 Skill 管理主流程。

## 推荐视觉方向

1. 页面主要使用一个基础表面，最多保留一个次级表面。
2. 普通列表使用间距和分隔线，不为每行创建卡片。
3. 统计摘要保留，但改为紧凑信息条，不使用四个独立重色卡片。
4. 状态优先使用图标、圆点和文字；只有冲突和危险操作使用强色。
5. 同一页面只保留一个主要按钮，其他操作进入次级按钮或菜单。
6. 使用系统 UI 字体，路径与命令继续使用等宽字体。
7. 圆角、边框、间距和字号收敛到统一 Token。
8. 宽屏增加有效信息，小窗口改变结构，不缩放整个界面。

## 建议视觉 Token 方向

- 页面背景：系统浅色或深色基础面。
- 侧栏：比内容区略有区分，但不使用独立大卡片包裹。
- 边框：只用于列表外框、分隔和弹层。
- 圆角：普通控件 `6–8px`，Dialog 和 Popover `10–12px`。
- 正文字号：`13–14px`。
- 页面标题：`22–24px`。
- 主色：保留一个克制 Accent。
- 状态色：成功、警告、冲突仅在需要的位置出现。

这些数值是原型起点，需要通过浅色、深色和四种窗口尺寸验证。
