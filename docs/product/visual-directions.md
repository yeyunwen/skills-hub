# skills-hub 三套视觉方向

- 状态：Ready for selection
- 日期：2026-07-26
- 共同基础：Codex 侧栏结构、独立环境模型、统计摘要、浅色/深色、自适应窗口

## 共同页面骨架

```text
┌ 环境侧栏 ┐ ┌ 当前环境：hermes · 已连接 ─────── 刷新 · … ┐
│ 本机     │ │ 统一技能库   已纳管   待同步   冲突       │
│ hermes   │ │ [搜索 Skill] [Agent 筛选] [状态筛选]     │
│ devbox   │ │                                            │
│          │ │ Skill 列表                                 │
│ 来源     │ │ browser       已同步     Codex  Claude …  │
│ 设置     │ │ github        冲突       查看差异          │
└──────────┘ └────────────────────────────────────────────┘
```

- 点击环境直接进入该环境 Skills。
- SSH 与本机使用同一页面，仅显示连接状态和环境名称。
- 统计摘要保留，但不再使用四个独立重色卡片。
- 跨环境对比和传输从右上角次级入口进入。
- Skill 列表是首屏主体，Agent 摘要用于筛选和快速查看。

## 方向一：Codex Quiet

### 关键词

安静、紧凑、列表优先、弱边框、开发者工具。

### 视觉

- 系统 UI 字体，路径使用等宽字体。
- 白色或深色基础面，侧栏只用轻微层级区分。
- 绿色仅用于主操作、成功状态和当前选中。
- 普通列表只有分隔线和 Hover 背景。
- 统计摘要是一条紧凑横向信息带。
- Agent 图标减少彩色面积，主要依靠文字与状态点区分。

### 交互

- 环境切换后始终进入 Skills。
- 行点击打开右侧详情 Drawer。
- 行内只保留一个主要动作，其他动作进入更多菜单。
- 冲突行直接显示“冲突”，并提供查看差异、保留、备份并接管。

### Motion

- `layoutId` 移动侧栏环境选中态。
- `AnimatePresence` 切换连接错误和重试提示。
- `layout` 处理列表新增、删除和筛选变化。
- 仅在跨环境传输时加入较明显的来源到目标进度动画。

### 适合

最接近用户提供的 Codex 截图，也是当前推荐方向。

## 方向二：Native Utility

### 关键词

原生、柔和、可靠、macOS 工具感。

### 视觉

- 侧栏使用轻微半透明或系统材质感。
- 内容区仍以平面列表为主，避免玻璃效果覆盖整个页面。
- 颜色更克制，状态点比状态色块更重要。
- 统计摘要使用图标、数字和短标签组合。
- Dialog、Popover 和 Drawer 更接近系统面板。

### 交互

- 环境侧栏显示连接状态、最近刷新时间和环境菜单。
- 远程断开时保留当前页面，顶部显示离线横幅。
- 跨环境对比使用双栏 Diff Drawer，而不是单独页面。
- 传输使用来源环境和目标环境的明确确认面板。

### Motion

- 侧栏宽度和当前环境背景使用平滑布局动画。
- Drawer 从右侧进入，内容与列表保持空间连续。
- 主题切换只做颜色过渡，不旋转、不放大页面内容。
- SSH 连接状态使用圆点、Spinner、Check 和 Error 的状态过渡。

### 适合

如果产品明确以 macOS 桌面体验为主，方向二会比方向一更有产品气质。

## 方向三：Motion Workspace

### 关键词

上下文连续、状态可见、轻动效、跨环境操作清晰。

### 视觉

- 基础视觉仍保持黑白灰和单一 Accent。
- 环境侧栏、统计筛选、Skill 列表之间拥有更强的连续关系。
- 跨环境对比和传输成为清晰的工作流，但不侵入默认首页。
- 统计摘要可以点击，点击后列表状态平滑过渡到对应筛选。

### 交互

- 切换环境时，标题和状态信息保持位置连续。
- 对比环境时，差异项以同一行的状态变换展示。
- 传输时显示来源、目标、目标 Agent 和冲突预览。
- 完成后目标环境列表自动更新，并高亮被影响的 Skill。

### Motion

- 环境选中态使用 shared layout。
- 统计筛选使用 shared layout 和列表 layout transition。
- Skill 传输使用阶段式进度：准备、上传、纳管、同步、完成。
- 冲突出现只做颜色和图标变化，不做抖动。
- Reduced Motion 下保留颜色、透明度和明确文本反馈。

### 适合

如果用户特别重视“操作过程有反馈”和“跨环境传输好理解”，方向三最合适。

## 共同响应式规则

- `1180 × 760`：完整侧栏、统计四列、Agent 四列。
- `900 × 650`：窄侧栏、统计两列、Agent 两列。
- `720 × 560`：图标侧栏或临时抽屉、Agent 单列、路径进入详情。
- 不整体缩小字体，不让页面产生整页横向滚动。
- 深色模式与浅色模式共享布局和组件状态。

## 共同不做

- 不再使用“远程设备”作为主导航模块。
- 不让每一行都成为独立卡片。
- 不用大面积绿色、红色和灰色背景表达普通状态。
- 不用动效掩盖加载慢、信息不清或操作路径复杂。
- 不把付费素材网站作为设计输入的必要条件。
